## 3. 画面の現状

| 項目 | 現状 | 分類 |
| --- | --- | --- |
| 経営メニュー | ゲストにも同じ画面とボタンを出している。押せないのは「今すぐ保存」と一部（`isHost` を見ている3か所）だけ | C |
| 閲覧専用の表示 | なし | D |
| ホストの更新の反映 | 開いている間、経営・従業員のタブは1秒ごとに描き直す。ほかのタブは操作したときだけ | B |
| 結果画面（閉店後） | 「次の日へ」はホストだけ（`resultScreen(..., host.isHost)`） | A |
| 「ゲストが経営画面を開くと固まる」 | **手元では再現しなかった**（Chromium）。考えられる原因: (1) 設定・遊び方がメニューの下に隠れ、押しても何も起きないように見えた（修正済み）、(2) 権限のない操作を押して通信の結果を待つ間（最大10秒）反応がないように見える、(3) レイアウト編集のロック待ち、(4) iPhone の Safari だけで起きる描画の問題 | E |

## 4. 再接続・退出

| 項目 | 現状 | 分類 |
| --- | --- | --- |
| 再接続後の役割 | 役割はサーバーが参加トークンとルームの `hostId` から決め直す（クライアントの申告は使わない） | A（`room.test.ts`） |
| ホストの退出 | ルームを終了し、最終状態を D1 に残す。ゲストは切断される | A |
| ホストの権限の移譲 | なし（ホストが戻るまで一時停止。別の人がホストになることはない） | A |
| ゲストの退出 | 持っていた物を戻して、ほかの人は続けられる | A |
| ホストがタイトルに戻るとき | 確認「共同経営から退出します」のあと退出。**ホストの端末のスロットには保存しない**（ルームの最終状態はサーバーにだけ残る） | C |

## 5. 結論（Phase 1 でやること）

1. `HOST_ONLY` を第2版の分類に合わせて広げる（経営に関わる操作はすべてホストのみ）。サーバーの `layoutLock` もホストだけにする
2. ゲストの経営メニューは閲覧専用にする（ボタンを無効にし、「閲覧専用（ホストが経営しています）」を表示）。権限のない操作はクライアントから送らない
3. 権限違反のときは状態を変えず、理由を返すだけ（今と同じ）。ゲストのセッションは切らない
4. テスト: サーバー側でゲストのすべての経営操作が拒否されること、ゲストの画面で操作ボタンが無効なこと
