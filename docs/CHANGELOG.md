- **有名人を32人・番組を12に**（すべて架空）: 前からいる8人の id はそのまま
- **サインの書き方を人ごとに**: 色紙の色と縁（金縁・二重線・角丸）・地の模様・字の色と太さ・明朝 / ゴシック・縦書き / 横書き / 斜め / くずし字・飾り（払いの線・二重の下線・星・ハート・丸囲み・どんぶりの絵・音符・王冠・ぐるぐる）・ひとこと（10種）を、出演者ごとに決まった組み合わせで描く

## 倍速の自動解除・貸し借りの即反映・クラウドセーブの廃止（2026-11-13）

- **イベントが起きたら等倍に戻す**（オーナーの判断・設定でオンオフ。初期はオン）: 店で珍しいことが起きたら倍速を解除し、終わるまで倍速にできない。対象は珍客イベント・YouTuber・テレビ取材・覆面調査員・珍しいお客さん（店にいる間）・SNS のバズ（続いている間）・クレーム・撮影や取材の許可の確認。爆発の火事・武器の事件は今までどおり設定に関係なく等倍。等倍に戻ったときは知らせ、速度のボタンを押すと理由を出す
- **倍速は次の日も続く**: 何も起きなければ、倍速は次の日・次に始めたとき（共通市場の読み直しも）もそのまま（端末の設定に残す）
- **企業間の貸し借りをすぐ反映**（オーナーの判断: 貸すお金は承認された時点で引く）: 端末で営業中の会社にも、お金を「届け物」にして数秒で届ける（営業中の端末は5秒ごとに受け取り、自分の操作の答えにも入る）。出金は端末のお金が足りるか確かめ、足りなければ断る（貸し出しは不成立・前倒しの返済はできない）。返事が来たらすぐ相手に入れる。日の確定では、サーバーが届けた入金だけを受け取る。端末が受け取らないまま営業が終わったときは、サーバーの状態で動かす
- **ひとりプレイ・共同経営のクラウドセーブを廃止**（オーナーの判断: サーバーのデータも消す）: 画面のクラウドに保存・読み込みと、サーバーの保存・読み込み・削除の API をなくした（前の版の端末には 410）。共同経営の保存はホストの端末にだけ残し、サーバーに控えを残さない。マイグレーション 0006 でクラウドセーブの表を消す。クラウドに保存できるのはオンライン市場（途中のセーブ）だけ
- テスト: core（珍しいことの間は倍速にできない・届け物の受け取りと返事・断る・二重に入れない・届けていない入金を受け取らない・受け取られなかった日の扱い）、サーバー（届け物の API・クラウドセーブの 410・表が消えている）、E2E（イベントで等倍に戻る・設定でオフ・倍速が設定に残る）

## 修正と変更: 売上のマイナス・融資・提供ミス・爆発の抽選・金色覚醒・FPS 式の武器（2026-11-13）

- **売上が −19,000円 ほどになる不具合**（2店舗）: 営業の終わりで結果を確定（共通市場）したあとに別の店へ入ると、今日の集計は入った店の日報に置き換わるのに、次の日へ回す分の基準が前の店のままだった。次の日の売上が「入った店 − 前の店」から始まり、マイナスになっていた。確定した日は店を移っても次の日へ回す分を足し続け、基準を入った店に合わせる。確定した日の日報も書き換えない
- **プレイヤー間の融資が振り込まれない不具合**: 貸し手が端末で営業中に借り手が承認すると、お金は貸し手の日の確定のときに動く。そのとき借り手の会社にもお金が入るが、サーバーは日を送った会社（貸し手）だけを保存していた。サーバーが読み直すと、契約は「返している最中」なのに借り手のお金が消えていた。操作の前後で状態の版が変わった会社をすべて保存する。端末は、開店のときにサーバーの状態が新しいとわかったら自動で読み直す
- **麺釜2台・盛り付け台2台で提供ミスが増える不具合**（測定で 29.7% → 0%）: 盛り付け台ごとに同じ注文の分の丼を並べて余った丼に、「そのまま」のトッピングや別の量の麺が入り、ほかの注文に回っていた。丼は台が何台あっても注文の数だけ並べる・従業員はコールを聞いた注文の丼だけに盛る・麺は量の合う丼にだけ入れる・割り当てのない丼は麺の量が合う注文にだけ回す・麺釜は届く盛り付け台で受けられる注文だけゆでる（離れた2台目の麺釜の麺がゆですぎで捨てられ、提供が半分になっていたのも直る。40杯 → 75杯）
- **爆発事故の抽選**（オーナーの判断）: ゲーム内の営業時間の10分ごとに抽選する。1回の確率は営業時間から逆算し、1日の合計は今までどおり初回 1.0%・2回目から 0.001%（10分ごとに1%では4時間で約21%/日になるため）。当たったら、当たった10分の時刻に火が出る
- **金色覚醒の髪型**: 元の黒髪・帽子などを隠し、頭全体をおおう逆立つ金髪にした（前・横・後ろ・うなじ・前髪。顔は見える。眉も金色）。覚醒すると房が伸びて逆立つ
- **武器を FPS 式に**（オーナーの判断）: 人に向けた「襲う」ボタンをなくし、武器を持っている間はいつも「撃つ・振る・投げる」ボタン（PC は F キー・左クリック）。照準の先で最初に当たる人に当たり、外れることもある。客は血を流して死に、その日の営業が終わるまで倒れたまま（座っていた客は通路へ倒れる）。店員はけがをしてその場に倒れ、翌日から1週間療養。共同経営の仲間は5秒倒れる。警察が来るまでは何人にでも使える。罰は、最初の事件の評判 −0.4 に加えて死者1人ごとに −0.1（1日 −1.5 まで）
- テスト: core（店を移ったあとの売上・2台ずつの提供ミス・10分ごとの抽選・FPS 式の武器と罰と仲間のダウン）、サーバー（融資のお金が読み直しても残る）、E2E（「撃つ」ボタン）

## じろ7 Phase 5・6: 独立したイベントの基盤と珍客イベント（UFO・金色覚醒・横バウンス・鼻ほじり・クマ「みつぐま」）（2026-11-12）

- **独立したイベントの基盤**（設計書 6）: 珍客イベントの定義（起こる確率・何日目から・クールダウン・大事さ・営業の邪魔になるか・夜と田舎の倍率・セリフ・まわりの客の反応・連鎖）を1つの表（`data/chaos.ts`）にまとめ、抽選・同時の上限（2つ）・1日の上限（2つ）・クールダウン・連鎖・記録は共通の仕組み（`sim/chaos.ts`）で行う。新しいイベントは表に1つ・処理に1つ足すだけで入る。どのイベントもほかのイベントを条件にしない（YouTuber がいなくても UFO は来る）。抽選は珍客イベント専用の乱数で引き、客の乱数・今までのイベントの乱数の並びは変えない
- **連鎖**: イベントが終わると、表の確率で別のイベントを数日起こりやすくする（例: UFO を見た客が何かに目覚めそう → 金色覚醒、ダンスの動画を見たクマが店を探している → クマ）。必ずではなく、連鎖の深さは2まで（無限につながらない）。起きた連鎖は「うわさ」として知らせ、イベントの記録に「前のイベントからの連鎖」と出す。同時に起きていたイベント（YouTuber の撮影・テレビ取材・ほかの珍客）も記録に残す
- **まわりの客の反応**: 主役の近くの客だけが、性格（好奇心・人と話す・流行に乗る・撮影する・SNS・迷惑への我慢。前のセーブの客は ID から決まる値）で、驚く・笑う・怖がる・撮影する・まねする・嫌がる・店員に知らせる。同じイベントに同じ客は一度だけ反応し、少しの間で元に戻る。よい珍事は居心地が少し上がり、迷惑は下がる。見た客・撮影した客の数を記録に残す（Phase 7 の SNS・話題性で使う）

- **居座り**: 団体がまれに食後も話し込み、席が空かない。🙏丁寧に声をかける・🚶混雑を説明する・🚪退店をお願いする。性格・混雑・言い方で、円満に帰る／気分を害する／断る
- **食べ方の汚い客**: 席や床を汚し、隣の客に飛ばす（嫌がるかは距離と客の性格しだい）。☝️注意する（改める・聞き流す・怒る）・🧻周りを拭く・💺嫌がっている隣の客に別の席へ移ってもらう・🚪退店を促す
- **店の前の喫煙**: 食後に店の前（「禁煙」の張り紙）でタバコを吸う客。並んでいる客が嫌がる。店の外へ出て🚭禁煙をお伝えする（すぐやめる・謝って去る・不満を示す・無視する）
- **トラブルと評価**: 迷惑を受けた客の満足度が下がり、口コミ・評判に表れる。早く適切に対応すると不満の一部が戻る。同じトラブルで同じ客を二度数えない。店員の口論は周りの客も見ている。日報にトラブルの数
- **従業員**: 食べ方の注意・居座る団体への声かけ（待ち客がいるとき）・店の外の喫煙客への声かけ
- 注: 団体の注文はまとめて作れるので、同じ人数でも提供が速くなり、店は少し楽になる（バランスは総合調整で見直す）

## 従業員の雇用・シフト・勤怠（第2版 Phase 2、2026-11-03）

オーナーの「営業・人事・マルチプレイ改良設計書」の 3〜5（判断は `docs/SALES_IMPROVEMENT_IMPLEMENTATION_PLAN.md`「第2版 Phase 2」）。

- **アルバイトと社員**: 採用はアルバイトから（時給。候補者の日給の目安 ÷ 4.5時間）。経営メニューの「従業員」で、勤務の記録と昇格の目安（勤務日数・遅刻欠勤・サボり・客とのトラブル・担当の能力）を見て「社員にする」と、日給（アルバイトの1日分 × 1.15）で毎日・仕込みから閉店まで勤務し、遅刻・欠勤が減る。接客担当がいないときは担当に関係なくクレームに対応する
- **シフト**: 7日周期の曜日（1日目 = 月曜）ごとに、出勤（仕込みから／11:00〜14:30）・退勤（11:30〜15:00）・休憩（なし・30分・60分）を30分刻みで決める。休みにする・すべての勤務日に同じ時間・今日の出勤状況（勤務中・出勤前・遅刻・休憩中・退勤・欠勤・休み）。給与は働いた時間ぶん（仕込みからの出勤は 0.5時間ぶん）。今日の予定を変えるとすぐ反映し、休みの人に勤務を入れると呼び出して少しあとに来る。初めのシフトは毎日・仕込みから閉店まで（今までと同じ働き方・同じ給与）
- **勤怠（隠しパラメータ）**: 低いほど 遅刻・当日欠勤（朝に1回だけ抽選）、勤務中のサボり・持ち場を離れる（一定の間隔で抽選、1日2回まで）、仕事の後回し（仕事を選ぶときに抽選）が起きやすい。同じ人が続けて休まない・遅刻しない。チュートリアル中は起きない
- **辛抱（隠しパラメータ）**: 低いほどクレーム対応で言い返して口論になる（客は★1の口コミを書いて帰る）・対応を途中で放棄する・態度が悪くなる。接客の能力とは別
- **成長**: 調理 → 調理、清掃・洗い物 → 衛生、接客 → 接客、配膳・運ぶ → 速さ・移動 が仕事をするたびに少しずつ伸びる（1日の上限あり）。勤務した日ごとに経験も増える
- **数値は見せない**: 勤怠・辛抱は画面に出さず、勤務の記録（「これまで遅刻はありません」「最近、欠勤が続いています」「客との口論が発生しました」など、実際に起きたことだけ）から推測する。能力の「信頼性（安定）」の表示はなくした
- 上部の日付に曜日を表示（例: 3日目（水））。サボっている従業員はスマホを見ている。言い返した従業員に吹き出し
- 古いセーブの従業員は社員として扱う（今までと同じ日給・毎日の勤務。「信頼性」は勤怠の初期値として読む）
- 共同経営: シフトの変更・昇格はホストだけ（サーバーで確認）。ゲストは記録とシフトを見られる

### ゲーム本体（`packages/core`）

- **チュートリアル**: 営業0日目（練習の日）を追加。仕込み → 在庫と発注 → 値段 → 設備の手入れ → レイアウト → 開店 → 1杯目を手順どおりに調理・提供 → 片付け（下げる・洗う・拭く・モップ）→ 2杯目は自分で → 閉店と精算 を1手順ずつ案内し、操作すると次へ進む。練習の売上・評判は残さず、終えると1日目から始まる。3日目には「従業員」の回を受けるか選べる（受けると採用を解放。雇うかどうかは途中で選べる）
- **片付けは「拭いてから下げる」**: 汚れた席は、カウンターを拭くまで丼を下げられないようにした（先に丼を下げると空いた席に次のお客さんが座り、拭けなくなっていたため。丼が置いてある間は席が空かない）。従業員も拭いてから下げる段取りにし、汚れが少ない席で片付けが止まらないようにした。マナーの良いお客さんは自分で拭いていくので、その席は拭かずに下げられる。チュートリアルと案内も「拭く → 下げる → 洗う」の順に変更
- 不具合修正: チュートリアルの「仕入れ」で進めなくなる。経営メニューを開いている間は時間が止まるのに、手順の進み具合は時間が進むときにしか確かめていなかったため、発注しても次へ進まず、発注を重ねて冷蔵庫がいっぱいになっていた。操作の直後に確かめるようにした（値段・設備・採用など、メニューの中で行う手順も同じ）。冷蔵庫がいっぱいでも醤油・一味唐辛子なら頼めることを案内に追加
- 不具合修正: クレームで返金したお客さん（食べずに帰る）の丼を下げられず、席も空かなかった。忘れ物を受け取って帰るお客さんが店内の待ち場所をふさいでいた
- 調理: ロット（盛り付け台のスロット）単位で丼を並べる → タレ → スープ → 麺ゆで（てぼ・茹で加減） → コール確認 → 麺上げ → トッピング → 提供。作り直し・冷め・のび・こぼしに対応
- コール: ヤサイ / ニンニク / アブラ / カラメ / 唐辛子（マシ・マシマシ・少なめ・抜き）。コールの聞き逃し・盛り間違いは満足度に反映
- 客AI: 行列 → 食券購入 → 着席 → 食事 → 退店。個性（常連・初見・せっかち等）、待ち時間・品質・清潔さで満足度と口コミが変わる。忘れ物・こぼし・汚れが発生
- 仕込み: 豚の煮込み → タレ・煮豚、豚切り、ヤサイゆで（キャベツ・もやし）、ニンニク刻み、背脂、スープ
- 在庫・発注: 消費期限・冷蔵庫容量・自動発注、欠品時の返金
- 経済: 現金と損益の分離、取引キーによる二重計上防止、家賃・給与・維持費・光熱費、延滞・融資・設備売却、救済も尽きると破産
- 設備: 購入・売却・修理・メンテナンス、摩耗による故障率の上昇
- 従業員AI: タスクボード方式（予約・失敗時の冷却・実行可能性の事前確認・在庫を見た仕込みの優先度）。採用・解雇・担当設定
- レイアウト: 0.5m グリッド、ゾーン・重なり・到達可能性・通路幅の検証、店舗拡張（8 → 12 → 16 → 22 席）
- 評判・キャリア: 星評価、口コミ、目標と解放
- セーブ: 3スロット、一時ファイル → 検証 → 世代バックアップ → 本体の順で書き込み、チェックサム、スキーマ移行。共同経営のゲストはホストのセーブに残さない
- 同期プロトコル: バージョン付きパッチ（キー付き配列）、requestId による重複排除、状態チェックサムでのずれ検出
- 入力検証: 操作要求（Action）の値を検証し、不正値を拒否

- Durable Object（SQLite）: 共同経営ルームの権威サーバー。最大4人、ホスト離脱時の一時停止、レイアウト編集のロック、定期チェックポイント
- D1（アカウント・クラウドセーブ・ルーム記録・監査ログ）。**R2 は使わない**（オーナーの判断。セーブ本体と共同経営の保存の控えも D1。[ADR-002](adr/ADR-002-no-r2.md)）
- D1 のテーブルは Worker が最初の要求のときに自分で作る（ダッシュボードの GitHub 連携でも、API トークンの権限追加やマイグレーションのコマンドが要らない）
- レート制限、オリジン制限、クライアントバージョン確認

### 開発・公開

- CI（GitHub Actions）: push で型チェック・単体テスト（core / server）・ビルド・E2E（iPhone 相当＋PC）
- GitHub Pages への自動公開（Pages の公開元が「GitHub Actions」でない間は公開をスキップして案内）
- Cloudflare へのデプロイ: リポジトリのルートで `wrangler deploy` すると失敗していたため、デプロイ先を `apps/server` に向けるスクリプト（`npm run deploy:server`）と手順を追加
- **Cloudflare へのデプロイを GitHub Actions で行う**（`.github/workflows/deploy-server.yml`。オーナーの判断: [ADR-003](adr/ADR-003-deploy-via-github-actions.md)）。GitHub の Secrets に Cloudflare の API トークンとアカウント ID を登録すると、push のたびにサーバーのテスト → D1 の用意（なければ作る）と ID の設定 → 秘密鍵 `SESSION_SECRET` の登録（未登録のときだけ。値は表示しない）→ デプロイ → 応答の確認 を行う。D1 の ID はリポジトリに書かない。ブラウザ版のビルドも同じ鍵でサーバーの URL を求めて埋め込む（`VITE_SERVER_URL` の登録が不要に）。Claude Code は push するだけで Cloudflare を更新でき、トークンは見ない。2026-10-28 に本番へデプロイし、通しの確認とブラウザ版への URL の埋め込みまで確認済み
