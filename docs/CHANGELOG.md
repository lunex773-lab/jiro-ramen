# 変更履歴

日付はコミット日です。詳細は `git log` を参照してください。

## 0.9.0（2026-10-27）

最初の公開候補。設計書の Phase 0〜12 をひととおり実装し、自動テストと画面確認で検証済み。

### ゲーム本体（`packages/core`）

- **チュートリアル**: 営業0日目（練習の日）を追加。仕込み → 在庫と発注 → 値段 → 設備の手入れ → レイアウト → 開店 → 1杯目を手順どおりに調理・提供 → 片付け（下げる・洗う・拭く・モップ）→ 2杯目は自分で → 閉店と精算 を1手順ずつ案内し、操作すると次へ進む。練習の売上・評判は残さず、終えると1日目から始まる。3日目には「従業員」の回を受けるか選べる（受けると採用を解放。雇うかどうかは途中で選べる）
- 不具合修正: クレームで返金したお客さん（食べずに帰る）の丼を下げられず、席も空かなかった。忘れ物を受け取って帰るお客さんが店内の待ち場所をふさいでいた
- 調理: ロット（盛り付け台のスロット）単位で丼を並べる → タレ → スープ → 麺ゆで（てぼ・茹で加減） → コール確認 → 麺上げ → トッピング → 提供。作り直し・冷め・のび・こぼしに対応
- コール: ヤサイ / ニンニク / アブラ / カラメ / 唐辛子（マシ・マシマシ・少なめ・抜き）。コールの聞き逃し・盛り間違いは満足度に反映
- 客AI: 行列 → 食券購入 → 着席 → 食事 → 退店。個性（常連・初見・せっかち等）、待ち時間・品質・清潔さで満足度と口コミが変わる。忘れ物・こぼし・汚れが発生
- 仕込み: 豚の煮込み → タレ・煮豚、豚切り、ヤサイゆで（キャベツ・もやし）、ニンニク刻み、背脂、スープ
- 在庫・発注: 消費期限・冷蔵庫容量・自動発注、欠品時の返金
- 経済: 現金と損益の分離、取引キーによる二重計上防止、家賃・給与・維持費・光熱費、延滞・融資・設備売却、救済も尽きると破産
- 設備: 購入・売却・修理・メンテナンス、摩耗による故障率の上昇
- 従業員AI: タスクボード方式（予約・失敗時の冷却・実行可能性の事前確認・在庫を見た仕込みの優先度）。採用・解雇・担当設定
- レイアウト: 0.5m グリッド、ゾーン・重なり・到達可能性・通路幅の検証、店舗拡張（8 → 12 → 16 → 22 席）
- 評判・キャリア: 星評価、口コミ、目標と解放
- セーブ: 3スロット、一時ファイル → 検証 → 世代バックアップ → 本体の順で書き込み、チェックサム、スキーマ移行。共同経営のゲストはホストのセーブに残さない
- 同期プロトコル: バージョン付きパッチ（キー付き配列）、requestId による重複排除、状態チェックサムでのずれ検出
- 入力検証: 操作要求（Action）の値を検証し、不正値を拒否

### ブラウザ版（`apps/client`）

- **iPhone の横向き専用に変更**: 横画面に合わせて HUD・タイトル・セーブスロット・経営メニューを配置し直した。横長の画面で左右が引き伸ばされないよう、3D の画角を横の画角（約100°）基準に変更
- **最初から横画面で表示**: 縦向きの画面（回転ロック中など）でも「横向きにしてください」で止めず、ゲームの表示ごと 90° 回して横画面で表示する（端末を左に倒して持つ。回転ロックがオフで横にしたときは回さない）。タッチの座標・レイアウト編集の座標も表示に合わせて直す。大きさの基準を画面（vw・@media）から表示（コンテナの cqw・@container）に変更し、ノッチとホームバーの安全領域も回した向きに合わせる
- **視点カーソルで狙った物を操作**: 画面中央の照準が重なっている物を必ず選ぶ（手が届かなければ名前と「近づいてください」を出す）。何にも重なっていないときだけ、照準のすぐ近く（約4°以内）で手の届く物のうち、一番照準に近い物を選ぶ（以前は正面から左右約56°の広い範囲で近い物を選んでいた）
- **操作ボタンを小さな丸に**: 絵文字＋短い名前（例: 🍜麺入れ・🥢麺上げ・🍽️提供・🧽洗う）。数（2玉・汚れ40% など）はボタンの隅に、押せない理由は照準の下に小さく出す。長押しの作業はボタンの周りの輪で進み具合を出す。チュートリアルと案内の文のボタン名も合わせた
- **案内を画面下の小さな帯に**: チュートリアルの案内と初心者向けの案内を、画面下に小さく横長の帯（2行まで、「…」で全文）で出す。帯の文字の部分はタッチを素通りさせ、移動スティックの操作を邪魔しない。通知は上部に移した
- **共同経営の参加コードを見つけやすく**: ルームを作ったら参加コードを大きく表示する待機画面（コピー・参加中の人数・「店に入る」）を出す。店の中でも画面上部に「コード ABC123 ・ 2人」を常に出し、押すと大きく表示してコピーできる
- 一人称 3D（Three.js）。スマホは画面左で移動・右で視点、PC は WASD＋マウス
- 3D モデルはすべてコードで生成（丼の中身はコールどおりに盛られる。ヤサイの山・豚・ニンニク・アブラ・唐辛子・汚れた丼）。人物・全設備・店舗・小物・湯気・湯面
- HUD: 時計・資金・評判・行列・伝票レール・通知・注視対象の詳細・操作ボタン（長押し対応）・初心者向け案内
- チュートリアルの案内パネル（手順・進み具合・「次へ」など）、対象の設備や席の上に出る目印、目印が画面の外にあるときの向きを示す矢印、押してほしいボタンやタブの強調。タイトルに「チュートリアル」を追加
- 遅い端末でボタンのタップが外れないよう、経営メニューのタブと HUD 上部は作り直さずに更新（押している間は再描画しない）。経営メニュー・レイアウト編集の表示中は 3D の描画を止めて電池を節約
- 経営メニュー（損益・在庫発注・価格・設備・従業員・店舗・セーブ設定）、2D のレイアウト編集
- 効果音（WebAudio）とコールの読み上げ（音声合成、設定で OFF 可）
- 画質設定（低・中・高）、ホーム画面に追加できるアイコン
- 共同経営（オンライン）: ロビー（ルーム作成・コード参加）、再接続、クラウドセーブ（競合時は内容を見せて選択）

### サーバー（`apps/server`, Cloudflare）

- Workers API: 匿名認証、プロフィール、バージョン確認、ルームの作成・参加・退出、クラウドセーブ（楽観ロック）
- Durable Object（SQLite）: 共同経営ルームの権威サーバー。最大4人、ホスト離脱時の一時停止、レイアウト編集のロック、定期チェックポイント
- D1（アカウント・クラウドセーブ・ルーム記録・監査ログ）。**R2 は使わない**（オーナーの判断。セーブ本体と共同経営の保存の控えも D1。[ADR-002](adr/ADR-002-no-r2.md)）
- D1 のテーブルは Worker が最初の要求のときに自分で作る（ダッシュボードの GitHub 連携でも、API トークンの権限追加やマイグレーションのコマンドが要らない）
- レート制限、オリジン制限、クライアントバージョン確認

### 開発・公開

- CI（GitHub Actions）: push で型チェック・単体テスト（core / server）・ビルド・E2E（iPhone 相当＋PC）
- GitHub Pages への自動公開（Pages の公開元が「GitHub Actions」でない間は公開をスキップして案内）
- Cloudflare へのデプロイ: リポジトリのルートで `wrangler deploy` すると失敗していたため、デプロイ先を `apps/server` に向けるスクリプト（`npm run deploy:server`）と手順を追加
- **Cloudflare へのデプロイを GitHub Actions で行う**（`.github/workflows/deploy-server.yml`。オーナーの判断: [ADR-003](adr/ADR-003-deploy-via-github-actions.md)）。GitHub の Secrets に Cloudflare の API トークンとアカウント ID を登録すると、push のたびにサーバーのテスト → D1 の用意（なければ作る）と ID の設定 → 秘密鍵 `SESSION_SECRET` の登録（未登録のときだけ。値は表示しない）→ デプロイ → 応答の確認 を行う。D1 の ID はリポジトリに書かない。ブラウザ版のビルドも同じ鍵でサーバーの URL を求めて埋め込む（`VITE_SERVER_URL` の登録が不要に）。Claude Code は push するだけで Cloudflare を更新でき、トークンは見ない。2026-10-28 に本番へデプロイし、通しの確認とブラウザ版への URL の埋め込みまで確認済み
