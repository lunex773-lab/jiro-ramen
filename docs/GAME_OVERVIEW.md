# 「次郎系ラーメン屋 経営シミュレーター」概要（AI への説明用）

この文書は、開発中のゲームの現状（2026-10-29 時点）を、ChatGPT などの AI に説明するためのまとめです。
最後の「相談したいこと」に質問や依頼を書き足して、そのまま貼り付けて使ってください。

## 1. どんなゲームか

- **ジャンル**: 一人称 3D の店舗経営シミュレーション。次郎系ラーメン店（大盛り・ヤサイ・ニンニク・アブラ・コールの文化）の店主になり、ラーメンを作って出しながら、仕入れ・値段・設備・従業員・店舗の拡張を判断して店を大きくする。
- **遊ぶ場所**: ブラウザ（主対象は iPhone の Safari、PC でも可）。インストール不要。GitHub Pages で公開中: https://lunex773-lab.github.io/jiro-ramen/
- **画面**: iPhone の**横向き専用**。画面の回転ロック中で Safari が縦のままでも、ゲームの表示ごと 90° 回して横画面で表示する（端末を左に倒して持つ）。ホーム画面に追加すると全画面で遊べる。
- **人数**: ひとりプレイ（3つのセーブスロット）と、**オンライン共同経営（最大4人）**。
- **素材**: 3D モデル・効果音はすべてコードで生成（外部の画像・音声ファイルなし）。店名・人物・口コミは架空。実在の店名は使っていない。
- **将来の目標**: App Store での公開（未着手）。

## 2. 1日の流れ

1. **仕込み（開店前）**: 豚の煮込み、豚切り、ヤサイゆで、ニンニク刻み、背脂、スープ炊きなど。経営メニューで仕入れ・値段・設備・レイアウトも準備する。
2. **営業（ゲーム内 11:00〜15:00、実時間で約9分）**: お客さんが行列 → 券売機で食券 → 着席。注文を作って提供する。
3. **片付け**: 食べ終わった席は**先にカウンターを拭いてから**丼を下げる（丼が置いてある間は次の客が座らない。先に下げると空いた席に座られて拭けなくなるため）。丼は洗い場で洗って丼棚に戻る。床のこぼれはモップで掃除。
4. **閉店・精算**: 売上・原価・家賃・給与・光熱費・維持費などが計算され、結果画面で確認。翌日へ。
5. 資金が尽き、支払期限を過ぎ、融資・設備売却でも払えなければ**破産**。

## 3. 調理とコール

- 手順: 丼を盛り付け台に並べる → タレ → スープ → 麺をゆでる（テボ。理想は約18秒、茹で加減あり）→ お客さんにコールを聞く（「ニンニク入れますか？」）→ 麺上げ → コールどおりにトッピング → 丼を持って提供。
- **コール**: ヤサイ / ニンニク / アブラ / カラメ / 唐辛子 を、マシ・マシマシ・少なめ・抜き で指定。聞き逃しや盛り間違いは満足度に影響。
- メニュー: ラーメン（小）・小豚・小豚ダブル・ラーメン（大）・大豚・大豚ダブル・小＋生卵（一部は解放制）。初期価格は小 950円〜。
- 作り直し、冷め、麺のび、こぼしなどの失敗がある。

## 4. 主な仕組み

| 仕組み | 内容 |
| --- | --- |
| お客さん | 個性（常連・初見・せっかち、価格への敏感さ、マナーなど）。待ち時間・味・接客・清潔さで満足度が決まり、口コミ・評判（★）になる。クレーム（作り直し / 返金）、忘れ物、床の汚れ、スープのこぼし |
| 在庫・発注 | 食材ごとの消費期限、冷蔵庫の容量（kg）、翌朝便（通常価格）と当日便（3割高・約60秒で届く）、閉店後の自動発注。欠品すると返金 |
| お金 | 現金と損益を分けて記録。初期資金 30万円。家賃（8席の店で日8,000円）・給与・維持費・光熱費。延滞・融資・設備売却 |
| 設備 | 麺釜・寸胴・煮込み鍋・野菜ゆで釜・仕込み台・盛り付け台・トッピング台・丼棚・洗い場・食洗機・冷蔵庫・冷凍庫・製麺機・券売機など約30種。購入・売却・修理・自動メンテ。摩耗で故障しやすくなる |
| 従業員 | 調理・接客・清掃の担当。能力（速さ・調理・接客・衛生・移動・信頼性）、日給と採用費。仕事の種類ごとの優先度を担当設定で変えられる。AI はタスクボード方式（予約・失敗時の冷却・実行可能かの事前確認） |
| レイアウト | 2D の編集画面で設備と椅子を配置（0.5m グリッド、通路幅・到達可能性の検証） |
| 店舗の拡張 | 8席 → 12席 → 16席 → 22席。建設費・休業日あり |
| キャリア | 目標を達成すると解放（例: 初めての一杯 → 累計10杯 → 黒字 → ★3.0 → 常連5人 → … → ★4.5 かつ1日120杯「行列の絶えない名店」）。大盛り・ダブル・食洗機・製麺機・大型設備・店舗拡張などが順に解放される |
| チュートリアル | 営業0日目（練習の日）。仕込み → 在庫と発注 → 値段 → 設備の手入れ → レイアウト → 開店 → 1杯目を1手順ずつ → 片付け → 2杯目は自分で → 閉店と精算。練習の結果は残らない。3日目に「従業員の回」を受けるか選べる |
| セーブ | 端末内に3スロット（世代バックアップ・チェックサム）。クラウドセーブ（サーバー）もあり |

## 5. 操作（iPhone の横向き）

- 画面の左側をなぞる: 移動（スティック） / 右側をなぞる: 視点。
- 画面中央の**照準**を設備や席に合わせると、右下に**小さな丸い操作ボタン**（絵文字＋短い名前。例: 🍜麺入れ・🥢麺上げ・🍽️提供・🧽洗う・🧻拭く・🧺下げる）が出る。遠いと「近づいてください」。縁が点線のボタンは長押しの作業で、周りの輪が一周するまで押し続ける。
- 案内（ヒント・チュートリアル）は画面下の小さな横長の帯。右上「☰ 経営」で経営メニュー（損益・在庫発注・メニュー価格・設備・従業員・店舗・キャリア・セーブと設定）。
- PC: WASD＋マウス、E で操作、1〜6 で他の操作、Tab で経営メニュー。
- 設定: 効果音・音量・コールの読み上げ（音声合成）・視点の感度・上下反転・画質（低/中/高。重いときは描画の細かさを自動で下げる）・動作の重さの表示（fps）。

## 6. オンライン共同経営

- ホストがルームを作ると、**6文字の参加コード**を大きく表示する待機画面が出る。仲間はタイトルの「オンライン共同経営」→「ルームに参加」でコードを入力。店の中でも画面上部に「コード ABC123 ・ 人数」を常に表示。
- ホストのキャリアで全員が同じ店を経営（資金・在庫・評判は共有）。ゲストのセーブは変わらない。ホストが切断すると一時停止し、同じコードで戻ると再開。
- サーバーが状態を持つ権威サーバー方式。クライアントは操作要求（Action）を送り、サーバーが検証・適用して差分（パッチ）を配る。重複送信の排除、状態のチェックサムによるずれ検出、再接続あり。

## 7. 技術構成

| 部分 | 技術 | 役割 |
| --- | --- | --- |
| `packages/core` | TypeScript | ゲームのルールとシミュレーションのすべて（決定的。状態はプレーンな JSON）。ブラウザ（ひとりプレイ）とサーバー（共同経営）の両方で同じコードを動かす |
| `apps/client` | Vite 7 ＋ Three.js 0.186 ＋ TypeScript（フレームワークなし） | 一人称 3D の描画、HUD、入力、経営メニュー、レイアウト編集、効果音（WebAudio） |
| `apps/server` | Cloudflare Workers ＋ Durable Objects（SQLite）＋ D1 | 匿名認証、ルーム（1ルーム＝1 Durable Object）、クラウドセーブ（R2 は使わず D1 に保存）、レート制限、オリジン制限 |
| 公開 | GitHub Actions | push で型チェック・単体テスト・ビルド・E2E。GitHub Pages へ自動公開。Cloudflare へ自動デプロイ（API トークンは GitHub の Secrets） |

- 設計の決定記録: Unity ではなく Web 3D（ADR-001）、R2 を使わない（ADR-002）、Cloudflare へのデプロイは GitHub Actions（ADR-003）。
- テスト: 単体テスト（core 約77件・server 61件・client 14件）、Playwright の E2E 22件（iPhone 横向き相当の画面＋タッチ、縦向きで回した表示、PC）。
- リポジトリ: https://github.com/lunex773-lab/jiro-ramen （作業ブランチ `SecondAKIRA`）。

## 8. 最近の主な変更

- 横画面に固定（回転ロック中でも回して表示）。照準が重なっている物を操作する方式に変更。操作ボタンを小さな丸に。案内を画面下の帯に。
- iPhone での重さ・操作の不具合を修正（タッチの取りこぼしで歩き続ける・視点が飛ぶ・ボタンが反応しない、など）。描画の解像度の自動調整。
- チュートリアルの「仕入れ」で詰む不具合を修正。
- 片付けを「拭いてから下げる」順に変更（拭こうとしたら次の客が座って拭けない問題への対処）。
- 共同経営の参加コードを見つけやすく。

## 9. まだできていないこと・確認していないこと

- iPhone 実機（Safari）での動作・操作感・性能の確認が十分でない（自動テストは Chromium で実施）。
- 実機のブラウザからの共同経営の確認。
- 長時間プレイでのバランス調整（シミュレーションでは、ひとりで1日 +6,000〜12,000円程度）。
- App Store 公開（ネイティブ化・審査）。
- 3D の見た目（コードで作った簡素なモデル）や音の作り込み。
